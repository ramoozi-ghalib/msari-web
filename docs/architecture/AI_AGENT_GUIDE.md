# 🤖 دليل وتعليمات حوكمة المطورين ووكلاء الذكاء الاصطناعي (AI Agent & Developer Governance Guide)

**المشروع**: منصة مساري (`msari_web`)  
**الملف**: `docs/architecture/AI_AGENT_GUIDE.md`  
**الصفة**: 📜 **دليل حوكمة إلزامي وقاطع لكل مطور أو وكيل AI يعمل على المنظومة**

---

> [!CAUTION]
> **قوانين حوكمة مشددة وإلزامية (Mandatory Governance Rules)**:
> يتوجب على أي مطور بشرى (Human Developer) أو وكيل ذكاء اصطناعي (AI Agent) يقرأ أو يعدل في مشروع `msari_web` الالتزام التام بالقواعد التالية دون أي استثناء.

---

## 📜 1. التعليمات القاطعة والإلزامية (Mandatory Directives)

### 1️⃣ قراءة الوثائق المعمارية أولاً (Read Architecture First):
قبل البدء بأي كتابة كود، أو إنشاء أفعال خادم (Server Actions)، أو إنشاء مكونات، **يجب قراءة الوثائق المعمارية التالية في مجلد `docs/architecture/` أولاً**:
- `docs/architecture/PROJECT_ARCHITECTURE.md`
- `docs/architecture/FINAL_DATA_ARCHITECTURE.md`
- `docs/architecture/ARCHITECTURE_DECISIONS.md`

### 2️⃣ حظر إنشاء أي مصدر بيانات جديد (No New Data Sources):
يمنع منعاً باتاً إنشاء أي مصدر بيانات جديد (مثل قواعد بيانات مستقلة، أو ملفات خزن جديدة، أو خوادم خارجية) خارج المصادر المعتمدة رسمياً بالوثائق.

### 3️⃣ حظر استخدام الـ SQL (No SQL Usage):
يُمنع منعاً باتاً استدعاء أو استخدام Prisma أو Supabase أو إنشاء جداول SQL جديدة. المرجع الموحد والوحيد لقواعد البيانات في المشروع هو **Firebase Firestore**.

### 4️⃣ عدم دمج بيانات التطبيق مع محتوى الموقع (Strict Layer Separation):
- بيانات الفنادق المحلية، الحجوزات، والمستخدمين تظل مرابطة بالتطبيق عبر مجموعاتها المشتركة بـ Firestore.
- محتوى الموقع، السيارات، تفاصيل الوجهات، الصفحات، والـ SEO تُبنى وتُدار حصراً عبر **Website CMS** بمجموعات Firestore المخصصة ببادئة (`web_`).

### 5️⃣ حظر تعديل المعمارية دون تحديث الوثائق (No Silent Architecture Changes):
يُحظر تعديل المعمارية أو هيكلة البيانات دون تحديث وتوثيق القرارات المعمارية أولاً في سجل `ARCHITECTURE_DECISIONS.md`.

### 6️⃣ اعتبار هذه الوثائق هي المصدر الوحيد للحقيقة (Single Source of Truth):
تُعتبر الوثائق المعمارية الموجودة في المجلد `docs/architecture/` هي المرجع الرسمي الوحيد والحاكم للمشروع، ويجب عدم افتراض أي شيء مخالف لما ورد فيها.

## ❓ 2. الأسئلة المعمارية المفتوحة (Open Architectural Questions)

> [!NOTE]
> إذا واجه المطور أو وكيل الـ AI أي تعارض، أو نقص، أو فجوة أثناء العمل، **يمنع التعديل والاجتهاد الشخصي** ويجب توثيق السؤال فقط بداخل هذا القسم والانتظار للبت فيه من قبل صاحب المشروع:

1. **التعامل مع ملفات الكود القديمة غير المستخدمة (Legacy Files)**: هل يتم إبقاء الملف التأسيسي `src/lib/prisma.ts` كأرشيف فقط دون استدعاء، أم تنظيفه لاحقاً لمنع اللبس؟
2. **استراتيجية الـ Fallbacks أثناء التصفح**: هل تُعتمد بيانات `src/data/destinations.ts` كطبقة حماية ثنائية دائمة عند تعثر الشبكة، أم الاستغناء عنها بعد اكتمال الـ Web CMS؟

## 📌 3. ملخص قواعد الحظر (Prohibited Actions List)

- ❌ ممنوع استخدام `prisma.client` أو `Supabase`.
- ❌ ممنوع تخزين محتوى تسويقي أو أسعار سيارات بداخل ملفات `TS/JSON`.
- ❌ ممنوع استخدام `useState` لتخزين بيانات يفترض حفظها بـ Firestore.
- ❌ ممنوع تجاوز طبقة الأمان `adminGuard` في أي Server Action للإدارة.
