## 🏛️ ADR-001: اعتماد معمارية البيانات ثلاثية الطبقات وفصل محتوى الموقع (Website CMS)

* **الحالة (Status)**: 🟢 **معتمد ورسمي (Accepted)**
* **تاريخ القرار**: 30 يوليو 2026
* **متخذ القرار**: Chief Software Architect & Owner

---

### 📋 1. السياق والمشكلة (Context & Problem Statement)
أظهرت عمليات التدقيق المعماري تداخل بيانات تطبيق الجوال مع نصوص ومكونات الموقع الإلكتروني، بالإضافة لوجود بيانات مخزنة بحالات مؤقتة بـ `useState` (مثل السيارات) وبيانات دمج كودية بملفات TypeScript (مثل تفاصيل الوجهات ونصوص الصفحات). أدى هذا التداخل لتعقيد عملية النشر وإعاقة تحديث محتوى الموقع بحرية.

---

### 🎯 2. القرار المعماري المعتمد (Architectural Decision)
تقرر بناءً على وثيقة **`Final Data Architecture Specification`** ما يلي:

1. **تقسيم البيانات نهائياً إلى ثلاث طبقات مستقلة**:
   - **الطبقة الأولى (Application Data)**: البيانات المشتركة مع التطبيق (فنادق، حجوزات، مستخدمين، بنوك) وتبقى كما هي.
   - **الطبقة الثانية (Website CMS)**: المحتوى الخاص بالموقع فقط وتُدار بالكامل من لوحة تحكم الموقع عبر مجموعات Firestore مخصصة ببادئة (`web_`).
   - **الطبقة الثالثة (External Providers)**: خدمات الـ APIs الخارجية المباشرة كالفنادق العالمية والطيران.
2. **استبعاد الاعتماد على قواعد البيانات الـ SQL (Prisma / Supabase)** والاعتماد الكلي الموحد على **Firebase Firestore**.
3. **حظر تخزين أو تعديل بيانات المحتوى أو السيارات بداخل ملفات TypeScript/JSON الكودية**.

---

### ⚡ 3. العواقب والنتائج المعمارية (Consequences)

#### 🟢 النتائج الإيجابية (Positive Consequences):
- **وضوح ملكية البيانات (Data Ownership)**: أصبح معروفا لكل جزء في النظام: أين يُخزن، من يديره، ومن يستهلكه.
- **استقلالية إدارة محتوى الموقع**: تمكين إدارة الموقع من تعديل الهيرو، السيارات، الوجهات، الـ SEO، والصفحات دون الحاجة لإجراء أي تعديل كودي أو Build جديد.
- **مرونة النشر والاستقرار**: إلغاء تعقيدات الربط بقواعد بيانات SQL متعددة وسهولة النشر على أي خادم سحابي بضغطة زر.

#### 🟡 القيود والالتزامات (Constraints):
- **الالتزام بالحوكمة**: يُحظر على أي مطور أو وكيل ذكاء اصطناعي (AI Agent) مستقبلاً إضافة مصادر بيانات جديدة أو إنشاء جداول SQL دون الرجوع وتحديث هذه الوثائق أولاً.
