# 🚀 دليل ووعد النشر للإنتاج (Production Deployment Guide)

**الصفة الرسمية**: Chief Software Architect, DevOps Architect, Release Manager, Technical Governance Officer  
**المشروع**: منصة مساري الرقمية (`msari_web`)  
**الحالة**: 📜 **دليل رسمي معتمد لكافة عمليات النشر والتشغيل للإنتاج (Official Production Release Guide)**

---

## 📑 1. الملخص التنفيذي (Executive Summary)

يحدد هذا الدليل الإجراءات المعيارية والقواعد الحاكمة لنشر وتحديث منصة مساري الرقمية (`msari_web`) على بيئات الإنتاج (Production) والبيئات المؤقتة (Staging). 

المستند الحاكم والمعماري لجميع البيانات هو مجلد `docs/architecture/`؛ حيث يلتزم فرق الـ DevOps والمطورين باتباع كافّة قوائم التحقق (Checklists) واستراتيجيات التراجع (Rollback) الواردة في هذا الدليل قبل وأثناء وبعد أي عملية نشر.

---

## 🎯 2. البيئات والاستضافات المدعومة (Supported Deployment Targets)

### 1️⃣ Hostinger Web Apps (Node.js Environment):
- **الوصف**: استضافة تطبيقات Web/Node.js المعتمدة للنطاق المؤقت والرسمي.
- **طريقة النشر المعتمدة**: رفع الكود المصدري كاملاً عبر أرشيف Linux POSIX القياسي (`.tar.gz`) أو عبر الربط التلقائي بمستودع GitHub.
- **أمر التجميع والتشغيل**: `npm run build` ثم `next start -H 127.0.0.1 -p 3000`.

### 2️⃣ Firebase Hosting / GCP Serverless (Dashboard & Static Proxy):
- **الوصف**: نشر واستضافة الواجهات والمحتوى الديناميكي عبر سيرفرات GCP الموزعة لتأمين سرعة الوصول للوحة التحكم والموقع.

### 3️⃣ Future Cloud / VPS / Vercel:
- **الوصف**: خيارات توسع مستقبلية مرنة مع تفعيل خيار `output: 'standalone'` المدمج بـ `next.config.ts`.

---

## 📋 3. المتطلبات والشرط الأساسية للإنتاج (Production Requirements)

- **إصدار Node.js**: الإصدار `20.x` أو `22.x` (LTS).
- **إطار العمل (Next.js)**: الإصدار `16.2.1` (App Router).
- **لغة البرمجة (TypeScript)**: الإصدار `5.x`.
- **متطلبات البناء (Build Requirements)**: نجاح أمر التجميع `npm run build` خالي تماماً من أي أخطاء TypeScript أو Lint.
- **شهادة الأمان (SSL Certificate)**: تفعيل Let's Encrypt SSL إجباريّاً على النطاق مع تحويل حتمي من `http` إلى `https`.
- **النطاق والـ DNS**: ضبط سجلات `A Record` و `CNAME` و `TXT` بشكل صحيح وموجه لاستضافة النشر.

## 🔑 4. قائمة متغيرات البيئة المطلوبة (Required Environment Variables)

توضح هذه القائمة الوظيفة والغرض التقني لكل متغير بيئة دون ذكر أي قيم أو أسرار حقيقية:

| اسم المتغير (Key) | الوظيفة والغرض التقني (Description & Purpose) |
| :--- | :--- |
| **`NEXT_PUBLIC_APP_URL`** | رابط النطاق الأساسي والعلني للمشروع (تسمح بالروابط النسبية والـ SEO). |
| **`NEXTAUTH_URL`** | الرابط المعتمد لمنظومة المصادقة وتأمين جلسات تسجيل الدخول. |
| **`NEXTAUTH_SECRET`** | مفتاح التشفير والسر الأساسي لتوليد وتأمين رموز جلسات المستخدمين (JWT Tokens). |
| **`AUTH_SECRET`** | المفتاح السري التشغيلي الموثق لـ Auth.js V5. |
| **`AUTH_URL`** | الرابط المعتمد لمزود خدمة Auth.js في بيئة الإنتاج. |
| **`NODE_OPTIONS`** | خيارات خادم Node لتحديد أسبقية عناوين الـ DNS (`--dns-result-order=ipv4first`). |
| **`HOSTNAME`** | عنوان الربط الداخلي للربط مع موجهات Proxy الاستضافة (`127.0.0.1`). |
| **`PORT`** | رقم المنفذ المخصص لتشغيل خادم التطبيق (`3000`). |
| **`FIREBASE_ADMIN_*`** | مفتاح الاعتماد لخدمات فايبربيس لإدارة البيانات والصور على الخادم. |
| **`UPSTASH_REDIS_*`** | (اختياري) مفاتيح تحديد معدل الطلبات (Rate Limiting) لحماية السيرفر من الهجمات. |

## 📑 5. قوائم التحقق بالنشر (Deployment Checklists)

### 🔵 أولاً: قائمة التحقق قبل النشر (Pre-Deployment Checklist)
- [ ] تشغيل ومراجعة نتائج البناء محلياً عبر `npm run build` والتأكد من صدور حالة `✓ Compiled successfully`.
- [ ] مراجعة ملفات التوثيق بـ `docs/architecture/` ومطابقة كافّة التحديثات.
- [ ] التأكد من إضافة كافّة متغيرات البيئة بـ لوحة الاستضافة دون نسيان مفاتيح المصادقة.
- [ ] اختبار النشر على دومين مؤقت (Staging Domain) قبل النشر النهائي على النطاق الرسمي.

### 🟡 ثانياً: قائمة التحقق أثناء النشر (During Deployment Checklist)
- [ ] التأكد من رفع حزمة كود مصدرية معتمدة ومطابقة مع تراخيص POSIX Linux (`0755` للمجلدات).
- [ ] متابعة سجلات البناء (Build Logs) والتأكد من عدم وجود أي `EACCES` أو `Timeout`.
- [ ] التأكد من بدء وتشغيل خادم Node بـ `✓ Ready`.

### 🟢 ثالثاً: قائمة التحقق بعد النشر (Post-Deployment Verification Checklist)
- [ ] **الموقع العام**: فتح الرئيسية والتحقق من تحميل الصور والأيقونات.
- [ ] **لوحة التحكم**: تسجيل الدخول وتجربة التصفح وتغيير الصلاحيات.
- [ ] **المصادقة (Authentication)**: تجربة دخول خروج مستخدم وتوليد الـ JWT Cookie.
- [ ] **بيانات Firestore**: فحص استرجاع قائمة الفنادق والمدن.
- [ ] **الـ APIs الخارجيّة**: تجربة صفحة الفنادق العالمية وطيران.
- [ ] **ملفات الـ SEO والأداء**: فتح مسار `/sitemap.xml` و `/robots.txt` وتأكد استجابتها بـ 200 OK.

## 🔄 6. استراتيجية التراجع والإنقاذ (Rollback Strategy)

في حال حدوث أي خطأ مفاجئ أثناء أو بعد النشر:

1. **التراجع التلقائي من لوحة التحكم**:
   - الدخول إلى قسم **عمليات النشر (Deployments)** بالاستضافة واختيار آخر نسخة ناجحة (Previous Stable Deployment) والضغط على **Rollback / Activate**.
2. **العودة للنسخة المستقرة السابقة في Git**:
   - في حال الحاجة لإعادة رفع الكود، يتم استخدام آخر Git Commit هاش مستقر من الماستر وتجميع الحزمة مجدداً.
3. **تفعيل صفحة الصيانة الوقائية (Maintenance Mode)**:
   - في حال تعثر الخدمة الخارجية يتم توجيه الطلبات لصفحة الصيانة الاحتياطية المعتمدة لضمان تجربة المستخدم.

## 🚫 7. قواعد وحوكمة الإنتاج الصارمة (Production Governance Rules)

- 🛑 **يُمنع منعاً باتاً النشر بدون بناء (Build) ناجح خالي تماماً من الأخطاء محلياً**.
- 🛑 **يُمنع النشر بدون قراءة ومطابقة وثائق المعمارية بـ `docs/architecture/`**.
- 🛑 **يُمنع تعديل متغيرات البيئة مباشرة بـ بيئة الإنتاج المباشرة أثناء ذروة التصفح دون اختبارها في Staging**.
- 🛑 **يُمنع النشر المباشر لأول مرة على النطاق الرسمي بدون اختبار المنظومة بالكامل على دومين مؤقت (Staging)**.
